## 2. 배경 및 목적

MSIG는 성도의 경제영성을 소득, 관리, 투자, 나눔의 관점에서 진단하고 현재 상태와 성장 방향을 제시하는 프로그램이다. 단순한 재정 상태 확인이 아니라 신앙, 경제 행동, 위험 노출, 나눔의 태도를 함께 점검해 성도가 하나님이 맡기신 재정을 지혜롭게 관리하도록 돕는 것을 목표로 한다.

본 서비스는 사용자가 온라인에서 80개 문항에 응답하고, 즉시 채점 결과와 해석을 확인한 뒤 상담 또는 코칭 신청까지 이어질 수 있도록 하는 웹 기반 진단 MVP이다.

## 3. 목표

- 사용자가 별도 회원가입 없이 MSIG 진단을 완료할 수 있다.
- 3개 파트, 총 80문항 응답을 안정적으로 수집한다.
- `result_guide.md` 기준으로 점수, 등급, 경제유형, 위험도, MSIG 행동 프로파일을 산출한다.
- 결과 화면에서 사용자가 자신의 강점, 위험 영역, 개선 방향을 쉽게 이해한다.
- 결과 확인 후 상담하기 버튼을 통해 실제 상담 채널로 이동할 수 있다.
- Figma 디자인을 기준으로 PC와 모바일 화면을 구현한다.

## 4. 비목표

- 회원가입, 로그인, 관리자 페이지는 포함하지 않는다.
- 서버 저장, DB 저장, 상담 신청 데이터 보관은 포함하지 않는다.
- 결제, 예약 캘린더, 알림톡, 이메일 발송 자동화는 포함하지 않는다.
- 검사 결과의 의학적, 법률적, 투자 자문적 판단을 제공하지 않는다.

## 6. 사용자 흐름

1. 사용자는 랜딩 페이지에서 서비스 소개와 CTA를 확인한다.
2. `진단 시작하기`를 누르면 기본 정보 입력 또는 Part 1 문항 화면으로 이동한다.
3. 사용자는 Part 1, Part 2, Part 3 문항에 순차적으로 응답한다.
4. 각 파트 완료 시 다음 파트로 이동하며, 응답은 localStorage에 임시 저장된다.
5. Part 3 제출 후 분석 중 페이지를 보여준다.
6. 짧은 지연 후 결과 페이지로 이동한다.
7. 결과 페이지에서 종합 점수, 등급, 경제유형, 역량별 점수, 경제장애 위험도, MSIG 행동 프로파일을 확인한다.
8. 사용자는 `상담하기`, `결과지 인쇄/PDF 저장`, `다시 진단하기` 중 하나를 선택한다.
9. `상담하기`는 백엔드 없이 설정 가능한 외부 상담 채널로 이동한다.

## 10. 채점 요구사항

### 10.1 공통 척도

| 점수 | 의미 |
| --- | --- |
| 1 | 전혀 아니다 |
| 2 | 아니다 |
| 3 | 보통이다 |
| 4 | 그렇다 |
| 5 | 매우 그렇다 |

### 10.2 Part 1 채점

- 6개 역량 원점수를 합산한다.
- 삼손의 위험 감지 27~33번은 역산한다.
- 역산 공식: `변환점수 = 6 - 응답점수`
- 종합 점수: `Part 1 전체 원점수 / 200 * 100`
- 역량 백분율: `역량 원점수 / 역량 최고점 * 100`

등급 기준:

| 등급 | 점수 | 평가 |
| --- | --- | --- |
| A+ | 90점 이상 | 탁월 |
| A | 80~89점 | 우수 |
| B+ | 70~79점 | 양호 |
| B | 60~69점 | 보통 |
| C | 50~59점 | 주의 |
| D | 40~49점 | 경고 |
| F | 39점 이하 | 위험 |

### 10.3 경제유형 판별

`result_guide.md`의 우선순위 조건을 위에서부터 순차 검사해 첫 번째로 매칭되는 유형을 적용한다.

출력 유형:

- 아브라함형
- 나발형
- 야곱형
- 발람형
- 엘리야형
- 아간형
- 탕자형
- 므비보셋형

각 유형은 강점, 약점, 처방 문구를 함께 출력한다.

### 10.4 Part 2 채점

- 각 증후군은 3문항 합산, 최고점 15점이다.
- 위험도: `원점수 / 15 * 100`

위험 수준:

| 수준 | 기준 | 원점수 |
| --- | --- | --- |
| 양호 | 46% 미만 | 7점 이하 |
| 주의 | 47~72% | 8~10점 |
| 고위험 | 73% 이상 | 11점 이상 |

### 10.5 Part 3 채점

- 각 영역은 4문항 합산, 최고점 20점이다.
- 영역 백분율: `원점수 / 20 * 100`
- 가장 낮은 영역을 찾아 개선 안내를 출력한다.

## 11. 상담하기 요구사항

백엔드가 없으므로 MVP에서는 상담 신청 데이터를 자체 저장하지 않는다.

기본 정책:

- `상담하기` 버튼은 환경 변수 또는 설정 상수로 관리되는 외부 URL로 이동한다.
- 외부 URL 후보: 카카오채널, 구글폼, 네이버폼, Calendly, 교회/기관 상담 신청 페이지.
- 설정값이 없을 경우 전화 또는 이메일 링크를 대체 CTA로 제공한다.
- 결과 요약 데이터를 URL에 자동 첨부하지 않는다. 개인정보와 민감한 진단 결과 노출을 방지하기 위함이다.

향후 확장:

- 상담 신청 폼
- 결과 데이터 서버 저장
- 관리자 확인 화면
- 이메일/문자 알림
- 상담 예약 캘린더 연동

## 12. 데이터 저장 및 개인정보

MVP 저장 방식:

- 응답 데이터는 브라우저 localStorage에 저장한다.
- 결과 산출은 클라이언트에서 수행한다.
- 서버 전송은 하지 않는다.

주의사항:

- 결과 페이지에 개인정보 보호 안내를 표시한다.
- 공용 기기 사용 시 `다시 진단하기` 또는 `초기화`로 데이터를 지울 수 있게 한다.
- 이름과 교회명 입력은 결과지 표시 목적이며 필수 여부는 구현 전에 확정한다.

## 13. 예외 및 검증

필수 검증:

- 80개 문항이 모두 응답되어야 결과 산출 가능
- 잘못된 점수값은 무시하고 재응답 요구
- localStorage 데이터 구조가 깨졌으면 초기화 안내
- `/result` 직접 접근 시 응답 데이터가 없으면 랜딩으로 이동
- `/analyzing` 직접 접근 시 응답 데이터가 없으면 랜딩으로 이동

## 14. 접근성 및 반응형 요구사항

- 모든 버튼과 선택지는 키보드로 접근 가능해야 한다.
- 선택지는 스크린 리더가 현재 선택 상태를 읽을 수 있어야 한다.
- 색상만으로 위험 수준을 구분하지 않고 텍스트 라벨을 함께 제공한다.
- 모바일 화면에서 버튼과 선택지의 터치 영역은 충분히 확보한다.
- 결과 차트는 시각 요소 외에 수치 텍스트를 함께 제공한다.
